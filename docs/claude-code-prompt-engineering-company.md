# Промпт для Claude Code: прототип сайта компании по проектированию инженерной документации

> Документ можно скачать из репозитория как Markdown-файл: `docs/claude-code-prompt-engineering-company.md`.
>
> Скопируйте весь текст из раздела «Готовый промпт» и вставьте его в Claude Code в корне проекта.

## Как использовать

1. Откройте папку проекта в Claude Code.
2. Вставьте промпт из раздела ниже одним сообщением.
3. Если проект уже создан, замените в промпте блок «Технический стек» на фактический стек проекта.
4. После генерации попросите Claude Code запустить сборку, линтер и кратко описать, какие файлы были изменены.

---

## Готовый промпт

```text
Ты — Claude Code, senior frontend/full-stack инженер и UX/UI-дизайнер. Нужно создать аккуратный, современный прототип сайта для компании, которая занимается проектированием инженерной документации для промышленных, коммерческих и инфраструктурных объектов.

Работай в текущем репозитории. Сначала изучи структуру проекта, package.json/конфиги, существующие компоненты и стили. Не переписывай проект с нуля, если уже есть рабочая архитектура. Вноси изменения минимально необходимым набором файлов, сохраняя стиль кода проекта.

## Цель

Сделать кликабельный прототип корпоративного сайта, который можно показать заказчику как первый вариант. Сайт должен выглядеть как реальная инженерно-проектная компания: надежно, строго, технологично, без шаблонной «воды».

Основной результат: готовый интерфейс сайта с контентом на русском языке, адаптивной версткой и понятной структурой страниц/секций.

## Контекст бизнеса

Компания оказывает услуги по разработке инженерной и проектной документации:
- проектная документация для зданий и сооружений;
- рабочая документация;
- инженерные разделы: ОВиК, ВК, ЭОМ, СС, АПС, СОУЭ, слаботочные системы, автоматизация;
- BIM/3D-моделирование и координация разделов;
- обследование объектов и сбор исходных данных;
- сопровождение экспертизы и согласований;
- авторский надзор и техническое сопровождение проекта.

Целевая аудитория:
- девелоперы;
- промышленные предприятия;
- генподрядчики;
- управляющие компании;
- архитектурные бюро;
- заказчики коммерческой недвижимости.

Ключевое позиционирование: «Инженерная документация без хаоса: точные решения, понятные сроки, сопровождение до результата».

## Технический стек

Если в проекте уже есть стек — используй его. Если проект пустой или минимальный, выбери простой современный стек:
- Vite + React + TypeScript;
- CSS Modules или обычный CSS без тяжелых UI-библиотек;
- адаптивная верстка для desktop/tablet/mobile;
- без backend, формы пока имитируются на фронтенде.

Если используешь другой стек по факту репозитория, объясни почему.

## Структура сайта

Сделай одностраничный лендинг с навигацией по якорям. Если архитектура проекта удобнее для нескольких страниц — можно сделать отдельные роуты, но MVP должен быть простым.

Обязательные секции:

1. Header
   - логотип/название компании-заглушки: «ИНЖПРОЕКТ ДОК»;
   - навигация: Услуги, Процесс, Проекты, О компании, Контакты;
   - кнопка CTA: «Обсудить проект».

2. Hero
   - сильный заголовок про проектирование инженерной документации;
   - короткий подзаголовок;
   - две кнопки: «Получить консультацию» и «Смотреть услуги»;
   - 3–4 доверительных показателя, например: «12+ лет опыта», «180+ комплектов документации», «Сопровождение экспертизы», «BIM-координация»;
   - визуальный блок: схема, карточки документов, инженерная сетка, план здания или абстрактная техническая графика средствами CSS/SVG.

3. Услуги
   Сделай карточки услуг:
   - Проектная документация;
   - Рабочая документация;
   - Инженерные системы ОВиК/ВК/ЭОМ;
   - Слаботочные системы и безопасность;
   - BIM-моделирование;
   - Сопровождение экспертизы.
   Для каждой карточки: краткое описание, 3 пункта результата, аккуратная иконка.

4. Процесс работы
   5 шагов:
   - Заявка и аудит исходных данных;
   - Техническое задание и календарный план;
   - Разработка разделов документации;
   - Внутренняя проверка и координация;
   - Передача комплекта и сопровождение согласований.

5. Преимущества
   Отрази ценность для заказчика:
   - прозрачные сроки;
   - единая координация разделов;
   - снижение рисков замечаний;
   - понятная коммуникация;
   - готовность к экспертизе;
   - работа с изменениями в проекте.

6. Проекты / кейсы
   Сделай 3 демонстрационных кейса-заглушки:
   - промышленный корпус;
   - бизнес-центр;
   - складской комплекс.
   Для каждого: тип объекта, площадь, какие разделы выполнены, результат.

7. О компании
   Короткий блок о команде инженеров-проектировщиков. Тон: уверенный, профессиональный, без преувеличений.

8. CTA-блок
   Заголовок: «Нужен комплект инженерной документации?»
   Текст: «Опишите объект — подскажем состав работ, сроки и риски до старта проекта».
   Кнопка: «Оставить заявку».

9. Контакты / форма
   Поля формы:
   - имя;
   - телефон или email;
   - тип объекта;
   - комментарий.
   Кнопка отправки. Пока без backend: при отправке показывай понятное сообщение об успешной отправке/заглушке.
   Добавь контактные данные-заглушки: телефон, email, город.

10. Footer
   - краткое описание компании;
   - навигация;
   - контакты;
   - копирайт.

## Визуальный стиль

Стиль должен быть премиальным, техническим и сдержанным.

Рекомендации:
- фон: светлый, белый/серо-синий;
- акценты: глубокий синий, графитовый, бирюзовый или оранжевый как точечный CTA;
- много воздуха;
- аккуратные карточки;
- тонкие линии, сетки, инженерные паттерны;
- без стоковых фото, если в проекте нет ассетов;
- можно использовать CSS/SVG-иллюстрации: чертежные линии, сетки, узлы, карточки спецификаций.

Сайт должен хорошо смотреться на ширине 1440px, 1024px, 768px и 390px.

## UX-требования

- Якорная навигация должна плавно вести к секциям.
- CTA-кнопки должны вести к форме контактов.
- Header должен быть удобным на мобильных устройствах. Если делаешь бургер-меню — реализуй его аккуратно.
- Форма должна иметь базовую валидацию обязательных полей.
- Добавь состояния hover/focus для интерактивных элементов.
- Соблюдай доступность: semantic HTML, aria-label там, где нужно, контрастный текст, видимый focus.

## Контент и тональность

Пиши весь пользовательский текст на русском языке.

Тон:
- профессиональный;
- конкретный;
- уверенный;
- без канцелярита;
- без чрезмерных обещаний вроде «гарантируем прохождение экспертизы».

Избегай фраз:
- «команда профессионалов» без конкретики;
- «индивидуальный подход» как пустой штамп;
- «лучшие на рынке»;
- «100% гарантия».

## Ограничения

- Не добавляй тяжелые зависимости без необходимости.
- Не используй внешние изображения, если можно сделать визуал на CSS/SVG.
- Не ломай существующие команды запуска и сборки.
- Не удаляй существующий функционал без явной причины.
- Не оставляй TODO вместо видимого контента.
- Не добавляй секреты, реальные персональные данные или реальные реквизиты.

## Что нужно сделать пошагово

1. Изучи проект и коротко сформулируй план изменений.
2. Реализуй прототип сайта.
3. Проверь адаптивность в CSS.
4. Запусти доступные проверки: install/build/lint/test — только те, которые реально есть в проекте.
5. Исправь найденные ошибки.
6. В финальном ответе дай:
   - список измененных файлов;
   - команды, которые запускались;
   - результат проверок;
   - короткую инструкцию, как запустить сайт локально.

## Критерии готовности

Прототип считается готовым, если:
- есть полноценный первый экран с понятным оффером;
- есть все обязательные секции;
- сайт адаптивен;
- CTA ведут к форме;
- форма показывает результат отправки;
- контент выглядит реалистично для инженерно-проектной компании;
- сборка проекта проходит без ошибок;
- итог можно показать заказчику как первый визуальный прототип.
```

## Короткая версия для быстрого запуска

```text
Создай в текущем проекте современный адаптивный прототип сайта на русском языке для компании «ИНЖПРОЕКТ ДОК», которая занимается проектированием инженерной и рабочей документации для промышленных, коммерческих и инфраструктурных объектов. Нужен премиальный технический лендинг с секциями: Hero, Услуги, Процесс, Преимущества, Кейсы, О компании, CTA, Контакты с формой и Footer. Используй существующий стек проекта, не добавляй тяжелые зависимости, сделай CSS/SVG-визуалы вместо внешних картинок, добавь якорную навигацию, адаптивность, hover/focus-состояния и базовую валидацию формы. Весь текст — на русском, профессионально и конкретно. После реализации запусти доступные проверки сборки/линта и опиши измененные файлы и команды запуска.
```
